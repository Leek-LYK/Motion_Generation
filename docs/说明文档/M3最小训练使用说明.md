# M3 最小训练与 TensorBoard

M3 从随机参数训练 9,214,881 参数的 Tiny 两阶段去噪器，使用固定的 M2 动作特征与冻结文本缓存。实验目录为 `runs/m3_20261101/`，模型与日志不进入 Git。原始数据、M2 缓存、官方 Kimodo 源码和官方权重均不改写。

## 本轮实验

`subsets/train32.json` 固定 32 个完整的 60–90 帧训练事件：走路、慢跑、跳跃、抬臂各 8 条；`val` 中另取到 5 条匹配描述的观察样本。排除镜像 ID，并按源动作去重。保留原始文本、heading 和全训练集统计量。验证样本数量很小，指标只能用于观察，不能宣称泛化结果。`subsets/references/` 保存全部参考动作的 NPZ、CSV 和关键帧投影图；人工语义复核仍为 pending。

训练配置见 `configs/m3_tiny.json`：每阶段 4 层、宽度 256、4 heads、FF 1024，FP32，batch 16，AdamW 学习率 1e-4，无 weight decay；梯度裁剪 1。每个 batch 从固定小集合有放回采样。时间步均匀取 0–999，预测 x0。

排错损失为六个归一化特征组各自 masked SmoothL1 均值的平均；不是论文在物理空间的七项损失，暂不含 FK 项。网络 dropout、文本 dropout、约束和 heading 增广均关闭，采样使用 nocfg。EMA 每 10 步更新，decay 上限 0.995，并显式使用 `(1+updates)/(10+updates)` 的短跑 warmup。

队列先做 `single_clip` 的 1,000 步。仅当固定种子、无后处理、纯噪声 DDIM 的 world MPJPE 小于 0.15 m 且低于随机初始化的 30%，才进入 `text32` 的 10,000 步。此门槛仅用于单样本训练链路排错，不是论文指标或机器人部署门槛。达到步数后自动结束，不无限扩训。

## TensorBoard

地址：`http://localhost:6006/`。远程 IDE 用户需在 Ports 面板转发服务器端口 6006。

- `train/loss`：实际随机 batch / timestep 的训练目标。
- `train/root_pos`、`heading`、`joint_pos`、`joint_rot`、`joint_vel`、`contacts`：六组误差。
- `train/root_grad_norm`、`body_grad_norm`：裁剪前各阶段梯度。
- `fixed_train/*`、`fixed_train_ema/*`：固定样本和固定噪声下五档时间步的误差。
- `heldout_val/*`：小型独立验证观察集。
- `generation_raw/*`、`generation_ema/*`：从纯噪声生成后与对应参考的几何误差。多样本生成具有多解性，这些配对误差只用于本轮过拟合排错。
- Images 下的 `samples/*`：蓝色参考、橙色生成，统一世界尺度的 XY/ZY 投影。移动距离长的动作会显示得较小。

训练日志每 10 步写入，每 100 步固定验证并保存 latest/best_train。单样本每 250 步、32 样本每 500 步导出 raw 与 EMA 的 NPZ、无表头 36 列 wxyz qpos CSV，以及 PNG。CSV 为 30 Hz；没有执行动态仿真，也没有应用动作后处理。

服务器重启 TensorBoard：

```bash
cd /root/kube-user/lyk/project/project_mg
bash scripts/tensorboard_m3.sh
```

TensorBoard 2.20.0 依赖 `pkg_resources`，项目锁定 setuptools 80.9.0。脚本使用项目专属 TMPDIR，避开共享 `/tmp/.tensorboard-info` 的权限冲突。

## 状态、停止与恢复

`queue_status.json` 保存队列 PID、阶段及子进程 PID；各阶段的 `status.json` 保存实时 step，`metrics.jsonl` 保存训练标量。状态为 `budget_completed` 只表示跑完规定步数，不自动等于语义质量验收完成。`run.lock` 文件保留不表示进程仍在运行。

停止队列时向 `queue_status.json` 中核实后的队列 PID 发送 SIGTERM。队列将信号传给自己的训练进程；训练在当前 step 后保存 checkpoint 并退出，不再启动下一阶段。不要操作其他 GPU 任务。

在没有活跃队列时续跑：

```bash
source .venv/bin/activate
export CUBLAS_WORKSPACE_CONFIG=:4096:8
python -B -u scripts/run_m3_queue.py --experiment runs/m3_20261101
```

也可单独恢复 32 样本训练：

```bash
python -B -u scripts/train_m3.py \
  --subset runs/m3_20261101/subsets/train32.json \
  --run-dir runs/m3_20261101/text32 --steps 10000 --resume
```

Checkpoint 包含模型、EMA、优化器、step、独立 batch/noise generator 和 Python/NumPy/Torch RNG。数据、文本、代码与子集指纹必须匹配；当前实现不允许在原 run 上悄悄更换训练配方。训练扩散调度与采样调度隔离，采样不消耗训练 RNG。

## 独立采样与文本对照

```bash
python -B scripts/sample_m3.py \
  --run-dir runs/m3_20261101/text32 \
  --checkpoint best_train.pt --weights raw \
  --output runs/m3_20261101/manual_sample_seed42 --seed 42

python -B scripts/sample_m3.py \
  --run-dir runs/m3_20261101/text32 \
  --output runs/m3_20261101/prompt_swap_seed42 \
  --seed 42 --prompt-swap
```

第二个命令对四组训练文本使用完全相同的初始噪声、75 帧和 heading=0，避免把方向、长度或噪声差异误当作文本控制。它复用已有缓存文本，不加载语言模型、不接受任意新文本。

## 实现验证

`verification/report.json` 记录真实 CUDA 六步更新与中断恢复对照、模型/优化器/EMA/RNG 精确一致、padding 损失不变、独立采样 RNG/调度、相同种子 DDIM 精确一致，以及生成 CSV 全帧 MuJoCo forward 的有限值检查。MuJoCo forward 只验证运动学加载，不表示动态跟踪通过。
