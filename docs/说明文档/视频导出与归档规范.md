# G1 测试视频：导出与归档规范

视频目录统一使用 `project_mg/exports/`，与训练日志 `runs/` 分开。`exports/` 已加入 Git 忽略。目录同时体现**训练批次、具体 run、实际 checkpoint step、权重类型、checkpoint 内容哈希、导出时间、文本与 seed**。

```text
exports/
├── INDEX.md                            # 自动生成的视频索引
├── _models/
│   └── <完整 checkpoint SHA256>/
│       ├── checkpoint.pt               # 首次测试时独立复制，后续按哈希复用
│       ├── model.json                  # 原始 run/checkpoint 路径和哈希
│       ├── run_config.json
│       ├── subset.json
│       ├── stats/motion/               # 三组归一化统计
│       └── environment/                # 首次归档时的 pyproject.toml / uv.lock
└── m3_20261101/                         # 训练批次
    └── text32/                          # 训练 run
        └── step_010000_ema_<ckpt哈希前8位>/
            └── <导出日期时间+0800>__<文本缩写>__<文本哈希>__seed42/
                ├── replay.mp4          # 1280×720，30 FPS
                ├── poster.png          # 中间帧封面
                ├── contact_sheet.png   # 首／中／末帧检查图
                ├── motion.npz          # Kimodo 原始生成动作，无后处理
                ├── normalized_features.npy
                ├── qpos.csv            # MuJoCo Z-up；xyz+wxyz+29关节，米/弧度
                ├── root_trajectory.csv # time_s,x_m,y_m,z_m
                ├── text_embedding.npy  # 本次实际使用的冻结向量
                ├── manifest.json       # 完整来源、参数、文件哈希与完成状态
                └── source/             # 本次导出、渲染等代码快照
```

所有日期时间按 `Asia/Shanghai` 表示，目录含微秒，重复导出创建新目录，不覆盖旧视频。原始 checkpoint 路径可能在续训后变化，因此必须以内容 SHA 和 `_models/` 的独立快照为准。每个 checkpoint 只复制一次，不为每条视频重复复制约 141 MiB 的模型文件。

`manifest.json` 同时记录训练结束 UTC 时间、模型配置、M2 指纹、文本编码器指纹、归一化文件哈希、模型 XML 哈希、seed、heading、帧数、DDIM steps、raw/EMA、CFG、是否后处理以及 ffprobe 验证的编码信息。实际 prompt、向量和 qpos 一起保存，不需要重新生成动作即可复核视频轨迹。

## 一条命令导出

从项目目录执行：

```bash
source .venv/bin/activate
python -B scripts/export_m3_video.py \
  --run-dir runs/m3_20261101/text32 \
  --checkpoint latest.pt --weights ema --seed 42 \
  --prompt 'A person walks forward in short steps at a normal pace with their arms swinging back and forth.'
```

当前脚本复用 M2 中已有的 47,453 条冻结文本向量；`--prompt` 必须与缓存文本精确一致。对于缓存中不存在的新文本，脚本明确拒绝，需先使用已验证的 LLM2Vec 流程编码；不会悄悄替换成相似句子。

默认选取同文本的首个训练事件的长度和 heading，这有利于观察 M3 的过拟合结果。manifest 明确记录 `prompt_seen_in_training` 和 `reference_sample_id`，不得把此视频当作未见文本泛化证据。缓存中有但未用于本轮训练的文本，默认 75 帧、heading=0。

固定条件比较不同文本：

```bash
python -B scripts/export_m3_video.py \
  --run-dir runs/m3_20261101/text32 \
  --weights ema --seed 42 --duration 2.5 --heading 0 --ddim-steps 100 \
  --prompt 'A person jogs forward at a steady pace.'
```

比较时同时固定 checkpoint、raw/EMA、seed、duration、heading、DDIM steps。M3 只训练了 60–90 帧且没有 heading 增广；新时长/朝向组合可能超出其小样本覆盖范围，视频结果需要据此解释。

导出完成后自动更新 [视频索引](../../exports/INDEX.md)。也可手动执行 `python -B scripts/index_video_exports.py` 重建。索引只列出 `status=complete` 的正式结果，失败或被新版替代的调试版本保留在磁盘但不列入索引。

## 回放与视觉约定

- 使用 Kimodo 配套 G1 MJCF，新增的展示材质和灯光仅在内存生效，不改写原 XML。
- 左侧展示跟随根位置的机器人网格；地面橙色点显示已走过的根轨迹。
- 右侧展示全段 XY 轨迹：灰色全路径、橙色已走路径、蓝色起点、黄色当前位置。
- 画面顶部标注文本、训练 run、step、EMA/raw 和 seed；底部永久标注 **KINEMATIC REPLAY**。
- 按帧设置 qpos 并调用 `mj_forward`，没有 `mj_step`、控制器或物理跟踪。不会自动修脚滑、平滑或修改生成运动。
- 生成完整帧数，不抽掉失败帧；检查四元数、qpos 有限值和 MP4 编码帧数。ffmpeg 失败或渲染失败会将 manifest 标为 failed。

只有在后续加入固定 G1 tracker 并记录真实动力学 rollout 后，才能另设 `dynamic_tracking` 视频类型并报告跟踪成功率；不得更改本轮视频的含义。

## M4 研究：原始与限位解码分别归档

M4 的 `scripts/render_m4_candidate_review.py` 可回放已保存的受控生成，不会重新随机采样。默认 `--decoder legacy` 保留原导出路径；显式设置 `--decoder bounded-v1` 时，使用项目内的最近单轴限位投影。后者属于后处理，目录加 `__bounded_v1`，视频底栏写明 `bounded hinge projection`，manifest 记录解码代码 SHA、原始与投影后的限位/角速度诊断。

限位版同时保存 `motion.npz`（原始生成）、`qpos_legacy.csv`（原导出器结果）和 `qpos.csv`（实际回放）。它不改变根轨迹，不平滑、不做 IK 或脚接触修正；有限关节角并不代表连续、可跟踪或无穿地。研究幅度门槛继续使用原始生成动作，不能用投影后的数值替代。

```bash
python -B scripts/render_m4_candidate_review.py \
  --run-dir runs/m4_research_20261103/R3_D_high_noise \
  --probe-dir runs/m4_research_20261103/R3_D_high_noise/controlled_three_seeds_cfg2 \
  --seed 42 --decoder bounded-v1 \
  --report-name candidate_video_review_cfg2_bounded_v1.json
```

`--case jump_seen_text_new_motion` 可单独导出指定失败案例。换采样 seed 时，文件名与 manifest 均随之记录；所有重复视频仍使用新的时间目录。

## M5 physical-v2：修正版模型与统计

`runs/m5_physical_20261103/` 的模型使用修正后的原生关节坐标与独立训练统计，必须使用新脚本。旧 M3/M4 导出脚本不能替代它。

```bash
.venv/bin/python -B scripts/export_m5_physical_video.py \
  --run-dir runs/m5_physical_20261103/B1_small_norm7 \
  --checkpoint latest.pt --weights ema --seed 42 \
  --duration 2.5 --heading 0 --guidance 2 --ddim-steps 100 \
  --prompt 'A person jogs forward at a steady pace.'
```

文本仍须精确存在于冻结缓存。也可使用 `--sample-id <ID>` 替代 `--prompt`：默认采用该事件的长度与初始 heading，采样噪声按该 ID 和 seed 固定。手动 prompt 使用跨文本共享的采样 key，因此固定长度、heading 和 seed 后可以做文本置换对照。

默认 `--decoder bounded`，另存原生未限位 `qpos_unbounded.csv`、原始生成 `motion.npz` 与归一化特征；`--decoder unbounded` 可直接回放未限位结果。两者都不会平移根高度、修接触或平滑。导出记录实际训练起止 UTC、checkpoint 快照 SHA、physical 输入与训练视图指纹、统计、decoder、连续性/接触诊断和渲染代码。

目录在 `exports/m5_physical_20261103/<run>/step_<step>_<weights>_<SHA>/` 下，末层加入 `__physical_v2_bounded` 或 `__physical_v2_unbounded`，与旧表示视频区分。正在训练的 checkpoint 也可导出，但 manifest 的 `training_budget_completed` 与 `quality_accepted` 明确区分训练进度和质量验收。

`--blind-id Model_A` 可以隐藏画面中的训练 run 名称，真实模型身份保留在 manifest 中。正式盲评还须把视频复制到隐藏真实路径的评阅包，并将模型映射留在评阅包之外。

工程模型必须显式使用 `--engineering-fixture`；输出进入 `exports/verification/`，使用独立 fixture schema，不进入正式视频索引，也不算模型质量结果。完整视频与最终失败审阅仍须使用正式模型生成。

原缓存之外的已验证文本向量可以用 `--text-cache <目录>` 显式选择。目录须含 `COMPLETE.json`、`rows.json` 和 `embeddings.npy`，父编码器身份与模型一致，文件哈希通过检查。例：`--text-cache runs/m5_physical_20261103/review/authored_text_cache`。使用独立缓存时按 `--prompt` 精确选择；向量缓存指纹也写入视频 manifest。文本编码在独立进程中复用原 M2 配置，不能直接套用去噪器训练的 CUDA 设置后忽略一致性差异。

## M5 人工盲评包：公开视频与私有模型身份分开

`scripts/package_m5_blind_review.py --spec <配置.json>` 把已保存的 qpos 直接渲染为匿名 A/B 视频，不重新采样、平滑或修正轨迹。配置指定 Tiny/Small 的 checkpoint 与对应生成报告、评阅阶段及两个独立输出根目录。两个模型须使用相同实际训练终点，画面显示共同的真实 step；模型名用 Anonymous A/B 替换。

- 公开包：`exports/reviews/<匿名包ID>/`，包含离线 `index.html`、匿名视频、两份空 CSV、两份默认未声明的人工评阅 JSON 与文件哈希；相邻 `<匿名包ID>.zip` 仅收录公开文件。
- 私有记录：`runs/<训练批次>/review/private/<匿名包ID>/`，保存 A/B 模型映射、真实训练 run/起止时间/step/checkpoint SHA、父状态、输入与统计身份、逐段 qpos 副本、渲染来源和代码快照。组织者保留此目录，评阅者只接收公开 ZIP。
- 工程小包：公开目录位于 `exports/verification/`，不进入正式视频索引和 M5 人工验收。当前十二提示小包仅用于验证流程；正式评阅仍需冻结的 120 个平衡提示及两个完整 Small / 匹配 Tiny。

每个 Small 与每类提示内部的 A/B 数量平衡，试次顺序用私有随机键打乱。公开路径和 HTML/JSON 不含真实 run、checkpoint SHA 或私有映射。相同试次保留相同文本、长度、采样 seed、heading、CFG 与 DDIM 设置；不会根据模型表现删除或替换提示。

两位评阅者使用各自的浏览器配置或设备，分别打开 `index.html`，选择评分文件槽、填写本人 ID，独立判断两段主动作、总体偏好和适用跳跃的起跳/腾空/落地。页面可同时播放两段，保留分槽草稿，分别导出 CSV 与评阅声明 JSON。所有分数初始为空，声明初始为 false；动作方向、速度、停步、手臂和接触问题记入备注。页面操作记录不是自动语义评分。

组织者收齐两份 CSV 与两份声明后运行：

```bash
.venv/bin/python -B scripts/analyze_m5_blind_review.py \
  --private-package runs/<训练批次>/review/private/<匿名包ID> \
  --ratings /path/to/rater_1.csv /path/to/rater_2.csv \
  --attestations /path/to/rater_1_attestation.json /path/to/rater_2_attestation.json \
  --output /path/to/review_result_revision1.json
```

分析前核对公开视频、试次信息、私有映射和原始 qpos 哈希；CSV 与声明允许人工填写，结果另记实际输入 SHA。缺少/重复试次、被改动的视频或 qpos 会拒绝。空白评分保持 pending，工程包和 `--synthetic` 测试均不能通过最终人工门槛；补充开发提示的分数也不会冒充最终源动作审计。

开发小包允许先收集一位真实评阅者的意见。使用独立的 `scripts/analyze_m5_single_rater_pilot.py --private-package <私有包目录> --ratings <本人CSV> --attestation <本人声明JSON> --output-dir <runs下的新归档目录>`，按实际人数保存原始文件快照、逐条解盲、主动作/偏好/完整跳跃的描述性统计。不会复制一份评分凑成两人，也不会通过最终人工门槛；原两人分析入口保持原要求。分析目录包含模型映射，应留在训练 run 中，不加入公开盲评 HTTP 根目录。首份真实单人反馈及范围见[单人盲评反馈分析](../科研进度/20261104_M5_单人盲评反馈分析.md)。

`source_final` 打包须提供冻结的审计放行文件、两个独立 Small 与 Tiny 的固定 80k checkpoint、完整 657 事件的新采样 seeds 评估，再严格使用已预选的 120 条源提示。打包和评分工具都不会自动启动审计、继续训练或宣告 M5 完成；完整课程、数值几何与全部其他验收证据仍需分别核实。
