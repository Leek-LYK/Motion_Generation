## NPZ 数据契约

设输出帧数为 T：

| 字段 | 内容 |
|---|---|
| `posed_joints` | `[T,34,3]`，世界坐标下的节点位置，米 |
| `global_rot_mats` | `[T,34,3,3]`，节点世界旋转矩阵 |
| `local_rot_mats` | `[T,34,3,3]`，Kimodo 骨架参考姿态约定下的局部旋转 |
| `root_positions` / `smooth_root_pos` | `[T,3]`，根位置及官方平滑根位置 |
| `global_root_heading` | `[T,2]`，heading 的 cos/sin |
| `foot_contacts` | `[T,4]`，官方逻辑在 30 Hz 下重算的接触标记 |
| `qpos_mujoco` | `[T,36]`，根 xyz 米、根四元数 wxyz、29 个关节角弧度 |
| `timestamps` / `source_frame_indices` | 相对源动作开头的秒数 / 原始帧号 `0,4,8,...` |
| `fps` / `source_fps` / `source_frame_count` | 30 / 120 / 实际源帧数 |
| `node_names` / `joint_names` | 34 节点 / 29 驱动关节的准确顺序 |
| `source_relative_path` / `source_sha256` | 原始 CSV 的路径与内容哈希 |
| `pipeline_fingerprint` / `official_split` | 处理配方指纹 / 官方划分 |

节点位置和旋转采用 **Kimodo Y-up、+Z forward** 坐标系；`qpos_mujoco` 为 **MuJoCo Z-up、+X forward**，不能混用。几何计算使用 float64，主要输出保存为 float32；时间戳为 float64。本轮尚未生成 417 维归一化特征、文本窗口或 embedding。

## 转换与检查

流程：解析 CSV → schema、帧数和 Frame 检查 → 取 `0,4,8,...` 帧 → 厘米/度转米/弧度，root Euler 转四元数 → 按官方 G1 XML 映射关节 → 官方 FK → 在 30 Hz 下重算派生字段 → 检查并保存。

不走 50→30 Hz 插值；未添加抗混叠滤波、关节限幅或动作裁剪。保留官方 smooth-root 算法。快速动作、接触和动力学质量仍需后续评估。

逐文件检查源数值有限、实际帧数等于元数据、Frame 从 0 连续编号、输出 shape 正确且全部有限；局部/全局旋转的正交性及行列式误差均不超过 `1e-4`。NPZ 序列化后再检查主要 shape 和版本，先写 `.tmp` 再原子改名。manifest 记录源/输出哈希、帧数、体积、误差和失败原因。

不合格动作记为 `failed`，不静默修补。`complete` 仅表示这些数值检查通过，不表示文本对齐、关节限位、接触质量或物理跟踪已通过。

## 断点续跑

已有输出仅在 manifest 标记完成、文件存在且体积匹配时跳过。为避免扫描开销，续跑不重新读取全部文件做 SHA-256；输出哈希在 manifest 中，可另做完整性审计。续跑期间不要修改原始数据。

```bash
# 前一个任务退出后运行；活跃实例存在时文件锁会拒绝重复启动。
python -B scripts/prepare_g1_nodes.py run --workers 16

# 排查原因后显式重试失败项。
python -B scripts/prepare_g1_nodes.py run --workers 16 --retry-failed
```

源码、骨架、元数据、划分、依赖和脚本指纹改变时，程序拒绝继续写同一输出目录。更换配方应使用新的 `--output` 版本目录。

需要停止时向 `status.json` 中的父进程 PID 发送 `SIGTERM`，程序停止派发并收尾在途任务；状态变为 `stopped` 后可续跑。异常断电后少量尚未提交的任务可能重新转换，未写完的 `.tmp` 不算成功输出。
