# M4-A/B/C/D 顺序实验

M4 用同一 Tiny 网络和冻结 M2 输入研究数据规模、文本 dropout/CFG 与 heading 增广。四组按 **A 训练与评估 → B 训练与评估 → C 训练与评估 → D 训练与评估** 顺序执行。每组独立随机初始化，使用相同 seed=20261102，不加载上一阶段权重。阶段顺序不代表模型权重串联。

## 固定实验配置

| 阶段 | 训练事件 | 文本 dropout | heading 增广 | 生成评估 |
|---|---:|---:|---|---|
| A | 256，四类各 64 | 0 | 无 | CFG weight 1，即无引导 |
| B | 1,024，四类各 256，包含 A | 0 | 无 | CFG weight 1 |
| C | 与 B 完全相同 | 0.1 | 无 | weights 1 / 1.5 / 2 |
| D | 与 B 完全相同 | 0.1 | 每段独立均匀 yaw 旋转 | weights 1 / 1.5 / 2，加旋转验证 |

配置分别位于 `configs/m4_A.json` 至 `m4_D.json`。网络沿用 M3 的 9,214,881 参数两阶段 Tiny：每阶段 4 层、宽度 256、4 heads、FF 1024；网络 dropout 固定为 0，FP32，batch 16，AdamW lr=1e-4、weight decay=0，梯度裁剪 1。目标仍为六组归一化 SmoothL1 均值的平均，未加入 FK 项。

训练上限每组 5,000 步；每 250 步完整验证。第 2,000 步起累计验证停滞，EMA 验证指标连续 8 次没有至少 0.1% 相对改善时提前结束。正常跑满或早停都进入下一阶段；不会因为 A 的泛化不佳而擅自跳过 B/C/D。数值、数据版本或程序错误会停止队列并保留恢复证据。

## 数据与评测边界

数据位于 `runs/m4_20261102/data/`。`A.json` 与 `BCD.json` 是冻结清单，B/C/D 复用同一文件。保留完整 60–90 帧事件、原文本与 M2 split；不重新裁剪、改写或移动官方测试数据。

四类为 walk、jog、jump、raise_arms。选择采用关键词互斥、场景/物体依赖排除、非镜像、同源动作去重和每句最多 8 个事件。优先覆盖不同文本。关键帧检查发现的跳台、障碍物和吸烟片段已经加入排除规则；旧筛选和初次冒烟结果保存在 `*_pre_review/`，不用于正式训练。

验证集固定 **64 条**：每类 8 条“已见文本的新动作”及 8 条“未见文本的同类动作”。这些未见文本从 A/B/C/D 训练候选中共同隔离；来源和 validation group 的 train/val 交集为零。已见文本分组的描述多样性有限，应同时查看两个分组和各类别结果。

“未见文本”是相对于本轮去噪器训练子集而言，文本编码器是冻结的预训练模型。它不等于未见动作类别或未见演员。M2 归一化仍基于完整训练池，所有实验共用，不将 256/1,024 宣称为归一化也只接触这些样本的严格小数据实验。

每条验证动作都有参考关键帧图和数值记录，见 `data/reference_review/`。助手关键帧检查与人工逐帧语义回放是不同证据；`human_semantic_review` 仍为 pending。正式队列属于已授权的探索实验，结束后还需回放质量判读。

## 完整验证与 checkpoint

每次验证遍历全部 64 条样本及 t=0/249/499/749/999，不再截断为 `val[:8]`。噪声按 sample_id 固定。先对每条事件的有效帧求均值，再对动作类别/文本分组等权汇总。raw 和 EMA 均评估，保存：

- `checkpoints/latest.pt`：可恢复的最新状态。
- `checkpoints/best_val_raw.pt`：raw 验证最优时刻的完整状态。
- `checkpoints/best_val_ema.pt`：EMA 验证最优时刻的完整状态；阶段末用其中 EMA 参数生成。

每个 checkpoint 保存优化器、EMA、step、最佳验证值、早停计数，以及彼此独立的 batch、扩散噪声、文本丢弃、heading RNG。采样与验证不推进训练 RNG。

D 在反归一化后同时旋转 root、节点位置、全局旋转、线速度和 heading，再归一化，最后恢复零 padding。项目内处理上游 `[B,T,J,3]` 旋转的广播边界，未修改官方源码。接触标记和高度不随 yaw 改变。

CFG 为 `unconditional + w * (conditional - unconditional)`；w=1 等于条件预测。A/B 不允许启用 w≠1，因为其无文本分支没有训练。

## 阶段结束后的自动评估

各阶段在自己的 `final_evaluation/` 保存：

- 最佳 EMA 的完整 native 验证，以及统一旋转 90° 后的验证；旋转验证不用于选 checkpoint。
- 全部 64 条验证动作、3 个 seeds（0/42/1234）的纯噪声生成。C/D 额外比较 CFG 1.5/2。
- 按动作类别、已见/未见文本汇总的配对 world/root-relative MPJPE、P95，以及逐样本脚穿地、预测接触覆盖与接触时脚速。
- 正确文本、跨类别打乱文本、全零文本的固定 t=999 诊断；A/B 的全零文本仍是分布外输入。
- 八条代表动作的 NPZ/CSV/PNG，以及相同 seed=42、75 帧、heading=0 的文本替换对照。

MPJPE 是配对诊断，生成有多解；脚速依赖预测接触，需同时查看接触覆盖；这些结果都不代表物理控制跟踪成功。阶段报告记录实际选中的 checkpoint step，而非把最终步数冒充最佳模型步数。

`comparison.json` 在各阶段评估完成后自动汇总。`QUEUE_COMPLETE.json` 表示四阶段都已正常执行并完成自动评估，不等于人工语义或泛化验收全部通过。

## 启动、状态和恢复

项目根目录下：

```bash
source .venv/bin/activate
export CUBLAS_WORKSPACE_CONFIG=:4096:8
python -B -u scripts/run_m4_queue.py --experiment runs/m4_20261102
python -B scripts/m4_progress.py
```

同一实验目录有排他锁，禁止启动第二个活跃队列。`m4_progress.py --watch` 每 10 秒只读显示状态。

队列启动前要求数值检查和 A→B→C→D 的两步完整冒烟链路通过。冒烟产物在 `queue_smoke/`，不会作为正式实验结果，也不出现在正式 TensorBoard 中。

需要停止时先核实 `queue_status.json` 的 PID 与实际命令，再向该队列发送 SIGTERM；队列仅通知自己的子进程，训练在安全边界保存。重新运行上面的队列命令会跳过完成的阶段，并恢复未完成训练或重新完成中断的评估。检查点和协议指纹不匹配时拒绝混合版本。

## TensorBoard

地址：`http://localhost:6007/`；远程 IDE 转发 **6007**。原 M3 的 6006 保留。

```bash
bash scripts/tensorboard_m4.sh
```

四个 run 显示为 M4-A/B/C/D。重点曲线：

- `validation_ema/macro_loss`：早停与 best-val EMA 的选择指标。
- `validation_ema/cohorts/*`、`groups/*`：新实例/新文本及各类表现。
- `validation_raw/*`：对应 raw 参数。
- `validation_ema/evaluated_events`：每次必须为 64。
- `train/text_drop_fraction_cumulative`：A/B 为 0，C/D 接近 0.1。
- `train/heading_abs_delta_mean`：仅 D 非零。
- `train/sample_exposures`、`equivalent_passes`：避免只按 step 比较数据规模。

模型、数据缓存和源码指纹在各 run 中固化，M2/M3 产物保持原样。后续导出视频仍按训练批次、run、checkpoint、导出时间归档，不混入 M3 视频目录。
