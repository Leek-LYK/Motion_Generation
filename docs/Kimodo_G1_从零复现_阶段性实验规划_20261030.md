# Kimodo G1 动作生成模型：从零复现的阶段性实验规划

> **版本**：v1.0｜2026-10-30  
> **硬件**：单张 NVIDIA B200 训练卡  
> **已有资源**：SEED G1 动作数据、英文语义标注、Kimodo 官方开源权重、LLM2Vec 所需语言模型权重  
> **研究目标**：独立训练一个能根据英文文本生成 Unitree G1 全身运动序列的模型；在验证训练链路后逐步接近 Kimodo 的运动质量与可控能力。  
> **规划性质**：面向落地实验的建议方案；其中“论文事实”与“建议实验配置”严格区分。此文未实际读取服务器上的数据和环境，所有通过标准需由实验记录验证。

---

## 0. 总体结论与边界

**建议主路线：官方推理基线 → 数据格式/运动表示验证 → Tiny 模型过拟合 → Tiny 文本生成 → 约 56M 参数级别的 Kimodo-Small → 约束条件训练 → 大规模训练与 Sim2Sim 验证。**

先把三个概念分开：

1. **运行官方模型（Inference Reproduction）**：使用官方权重生成动作。这验证依赖、数据接口和参考输出，**不代表复现了训练**。
2. **从零训练去噪器（Training Reproduction）**：LLM2Vec 采用已有预训练权重，先冻结并预计算文本 embedding；**Kimodo 去噪网络随机初始化**，使用自己的 SEED G1 数据训练。这是本项目的主目标。“从零”不要求重新预训练 8B 语言模型。
3. **官方级别完全复现（Full-scale Reproduction）**：重建论文的两阶段结构、数据增强、课程训练、损失和评测，并接近公开模型质量。**不能保证在单卡 B200、现有数据范围内达到官方最优指标**。

**当前已公开的能力边界**：截至 2026-10-30，官方 GitHub 仓库提供模型前向结构、扩散采样、动作表示与转换、推理/演示和 benchmark；**未提供可直接调用的完整训练入口与数据训练流水线**。因此应复用官方 `TwostageDenoiser`、`KimodoMotionRep`、`Diffusion`、G1 骨架和导出工具，自行实现 Dataset、训练循环、损失、采样、优化器、EMA、checkpoint 与验证代码。官方 GitHub Issue #25 仍在询问训练/微调代码发布计划。[1][2][3]

**不要把当前目标扩成**：从零训练文本大模型、端到端闭环机器人策略、任意长度无缝生成、G1 实机即插即用。Kimodo 生成的是**运动学参考动作**；真实动力学可跟踪性需要另行验证。

### 0.1 最终可验收交付

- `train.py` 能从随机参数启动并中断续训；至少一份 **Tiny / Small** 的自主训练 checkpoint。
- 文本输入 → 30 Hz G1 运动生成 → Kimodo NPZ / MuJoCo qpos CSV 导出 → 可视化回放的完整流水线。
- 独立的训练/验证/测试划分，固定的 prompts 和随机种子；训练损失、语义一致性、动作质量与失败样本报告。
- 与官方 `Kimodo-G1-SEED-v1` 在**同一测试条件下**对比，并对输出的运动进行 G1 Sim2Sim 可跟踪性筛选。

## 1. 先认清官方 Kimodo 的核心设计（不可跳过）

### 1.1 不是自回归动作 Token 模型

Kimodo 属于 **Explicit Motion Diffusion**：直接对逐帧的连续运动特征加噪、去噪，而不是先训练 VQ-VAE 离散动作 token 再由 LLM 自回归生成。条件包括文本 embedding、首帧朝向和可选的动作约束；推理通常用 DDIM 迭代去噪。[4]

每帧特征在论文中由以下部分组成：

| 部分 | 内容 | 作用 |
|---|---|---|
| `r_p` | 平滑后的全局 root 位置（3 维） | 稳定轨迹和路径约束 |
| `r_a` | 全局 heading 的 `cos/sin`（2 维） | 方向约束 |
| `j_p` | 各关节位置（每关节 3 维） | 几何及稀疏位置约束 |
| `j_v` | 各关节世界系速度（每关节 3 维） | 运动连续性 |
| `j_a` | 各关节世界系旋转的 6D 表示（每关节 6 维） | 稳定旋转表示 |
| `f` | 左右脚跟/脚尖 4 个接触标记 | 脚滑与接触控制 |

论文给出的两阶段架构：

```text
英文动作描述 ──> 已有 LLM2Vec (冻结/预计算) ──> Text embedding (4096 维)
                                                      │
G1 关节序列 ──> KimodoMotionRep ──> x0 ──> 扩散加噪 xt ──┤
                                                      ▼
                        Root Transformer → 预测平滑 global root
                                                      │
                                   global root → local root（转换）
                                                      │
                        Body Transformer → 预测各关节/body 特征
                                                      │
                                                预测 x0
                                                      │
                                            DDIM 反向采样
                                                      │
                                     NPZ / G1 qpos CSV / 可视化
```

**复现易错点**：每一个扩散去噪步骤内都执行 Root → Body；不是先把完整 root 序列扩散结束，再运行一次 Body。官方 `twostage_denoiser.py` 在训练态对预测 root 的 local 表示使用 `detach()`，实现时注意与原代码保持一致。[3][4]

### 1.2 官方网络与训练参数：参考值，不等于第一轮推荐配置

| 内容 | 论文或公开模型参数 |
|---|---|
| 全尺寸去噪器 | 两个 Transformer encoder；**每个 16 层、8 heads、宽度 1024**，合计约 **282M** 可学习参数 |
| 官方缩放实验 | 约 **56M（Small）/ 148M（Medium）/ 282M（Large）** |
| 官方 G1-SEED v1 配置 | `G1Skeleton34`；`fps=30`；`latent_dim=1024`；`ff_size=2048`；`num_layers=16`；`num_heads=8` |
| 文本条件 | LLM2Vec；单个 4096 维文本向量；论文另加入 49 个全零 extra tokens |
| 扩散 | DDPM 训练 `T=1000`；DDIM 推理默认 100 steps；模型预测 **干净运动 x0** |
| 优化 | Adam-atan2，学习率 `2e-5`；训练前 500k steps 纯文本、后 500k steps 加约束 |
| 最佳报告设置 | 30 Hz、最长 10 秒；16 张 A100 80GB、global batch 2048 |
| 损失 | 平滑 L1 的 root位置、heading、joint位置、速度、旋转、接触、FK 一致性共 7 项 |
| 分类器自由引导 | 文本 dropout 10%；默认 text/constraint guidance 权重均为 2 |

来源：Kimodo 技术报告 §4.1–4.4、§6.3，以及 `nvidia/Kimodo-G1-SEED-v1/config.yaml`。[4][5]

> **重要**：官方论文的 1M steps × global batch 2048 是**分布式全尺寸实验规模**，不可等同于单张 B200 的现实训练预算。先做真实单卡 benchmark（每 step 耗时、显存、吞吐），再决定可执行的 steps；不能凭算力宣传指标估算“几天训练完”。

## 2. 八个阶段：目标、实施内容、验收标准

> 时间为**工程排期建议**，默认单人主导、有可用服务器与数据权限；包含开发/排查，不代表保证完成时长。阶段可因数据问题延长。**每个阶段通过验收才进入下一个阶段**。

| 阶段 | 目标 | 实施重点 | 核心交付物 / Go-NoGo | 参考排期 |
|---|---|---|---|---|
| **S0：官方基线** | 证明环境、官方模型与 G1 导出可用 | 官方 G1-SEED 运行 4–6 组文本；NPZ、CSV、回放 | `baseline_outputs/`、模型版本/参数清单；输出无 NaN，正常回放 | 0.5–2 天 |
| **S1：数据契约** | 确定每条 G1 动作与英文标注**正确对齐** | 审计 CSV 格式、FPS、坐标系、关节顺序、文本时间戳、去重、分组切分 | `manifest.jsonl`、审计报告、train/val/test IDs；100 条抽样核对 | 2–5 天 |
| **S2：运动表示闭环** | G1 原始动作可无损/低误差转成 Kimodo 特征并重建 | 单位/旋转/坐标转换；30 Hz 重采样；FK、foot contacts、normalize / inverse | `csv -> NPZ/features -> inverse -> CSV`；指标与视频检查通过 | 3–6 天 |
| **S3：最小训练闭环** | 从随机初始化 Tiny 去噪器，在 16–64 条动作上过拟合 | 先仅训练 x0 回归 / 纯文本简单条件；固定数据与种子；训练器/EMA/存盘 | loss 显著下降；生成动作可辨识；断点续训与加载一致 | 3–7 天 |
| **S4：Tiny 文本生成** | 文本真正决定生成什么动作，而非只学平均姿态 | 256–2,000 段；分语义/动作类别；冻结文本 encoder；50–100 步采样 | 同 seed 改 prompt，动作类别可区分；独立验证集指标改善 | 4–10 天 |
| **S5：Small 模型** | 用 5k–30k 段训练约 56M 级两阶段模型 | 更长 3–6 秒；完整 root/body 表示；7项 loss、EMA；对比官方 | Small checkpoint、固定评测图表、相对 Tiny 的稳定改进 | 1–3 周 |
| **S6：控制能力** | 增加 keyframe、root path、手脚约束 | 从文本-only checkpoint 继续训练；逐步引入约束 mask/imputation | 约束误差下降，文本质量不过度退化 | 1–3 周 |
| **S7：全量扩展与应用** | 逐步扩至全部合格 SEED G1，并做 G1 Sim2Sim 复核 | 7–10 秒、数据增强、不同模型规模、导出与动作筛选 | 完整训练与评测报告、失败案例、可跟踪动作清单 | 2–4 周（视预算） |

**阶段顺序不要倒置**：如果 S2 运动重建仍有旋转翻转、轨迹错位或脚落地异常，直接扩到 10 万条只会把错误写进模型。

### S0：首先复现官方推理，而不是首先训练

**做什么**

1. 记录驱动、PyTorch/CUDA、显存、Kimodo Git commit，固定 Python 环境；优先用当前官方仓库而不是过时 fork。
2. 使用已有 `Kimodo-G1-SEED-v1` 权重，验证和 `nvidia/Kimodo-G1-SEED-v1/config.yaml` 对应；明确 LLM2Vec 的两份权重是否和官方一致。
3. 对走路、转身、蹲下、跳跃、倒地/起身、挥手等动作做 4–6 类定性基准。每类固定 3 个 seed，生成 3–5 秒；记录动作长度、推理耗时、显存与异常。
4. 分别检查**关闭后处理**和**开启后处理**的输出。后处理可能显著减少 foot-skate，不能把后处理改善归功于模型。

**已公开命令（运行前按服务器实际路径安装依赖并检查 `--help`）**：

```bash
# 在官方仓库内；建议建立单独虚拟环境，安装兼容本机 CUDA 的 PyTorch
pip install -e .

# 记录硬件/软件环境
nvidia-smi
python -c 'import torch; print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0))'
git rev-parse HEAD

# 官方命令：未显式指定的模型会自动下载，这里主动指定 G1-SEED
mkdir -p baseline_outputs
kimodo_gen 'A person walks forward.' \
  --model Kimodo-G1-SEED-v1 \
  --duration 4.0 \
  --seed 42 \
  --output baseline_outputs/walk_42

# 与 raw 生成对比，先查 --help 是否支持当前版本的 flag
kimodo_gen 'A person walks forward.' \
  --model Kimodo-G1-SEED-v1 \
  --duration 4.0 \
  --seed 42 \
  --no-postprocess \
  --output baseline_outputs/walk_raw_42
```

**验收**：至少 6 条可重放的 G1 动作，能正确生成/打开 NPZ 与 36 列 MuJoCo qpos CSV；如果权重/环境版本导致接口不匹配，**先修复版本兼容**再推进。[5][6][7]

### S1：统一 SEED G1 的真实数据格式与标注

**最高优先级风险：输入格式不是 Kimodo 推理输出格式。**

| 数据版本 | 常见约定 | 能否直接用 `kimodo_convert` 的 G1 CSV 路径？ |
|---|---|---|
| **官方 BONES-SEED G1 原始 CSV** | 官方 ProtoMotions 文档：120 Hz，含 `Frame`、root 平移（**厘米**）、root XYZ 欧拉角（**度**）、29 关节角（**度**） | **不能直接当作 36 列 qpos**。先解析列/单位/旋转与关节顺序，再转换。 |
| **你现有的处理版 G1 CSV** | 已在其他实验中使用的 50 Hz 数据（**以服务器实际内容为准**） | 需检查它是上述原始格式经降采样，还是已经改成 qpos。**不能假设**。 |
| **Kimodo 官方 G1 CSV** | 30 Hz，**36 列**：root xyz（米）+ root quaternion（wxyz）+ 29 DoF（弧度），**无表头与帧编号** | 可以使用官方 36 列 qpos 导入路径。 |

来源：ProtoMotions 的 SEED G1 CSV 和 Kimodo motion preparation 文档。[8][9]

**特别注意**：`G1Skeleton34` 是 **34 个骨架节点**（含额外脚趾节点等），**不是 G1 34DoF**；实际 qpos 导出是 29 个关节自由度，加 7 维浮动基座，共 36 列。否则无法正确重建足跟/脚尖接触信息。[5][7][10]

**S1 必做清单**：

- 统计文件数、动作总时长、每段时长、实际 fps、重复 ID、标注覆盖率；**不要把“约 12 万文件”直接等同于 12 万条有效训练样本**。
- 对原始 `Frame`、位置、欧拉角、关节列做 `schema` 映射；检查单位、欧拉旋转顺序、根节点轴、`wxyz/xyzw`，以及 G1 XML 的具体版本。
- 对文本字段标记**整段 overview**与**细粒度子片段**；统一用秒 `[start_s, end_s)` 对齐，抽帧之后重新计算帧号。先训练单句、单动作片段。
- 逐类抽查 100–200 条：walk、turn、jump、squat、kneel、crawl、acrobatic、gesture（按数据真实类别调整），可视化动作是否对应英文描述。
- 将原始 clip 的同一个 `source_motion_id`、拍摄 session / subject / 同源变体全部放入同一 split；**不可随机按窗口打散分训练/测试**，否则严重数据泄漏。
- 保存 `data/manifest.jsonl`、`data/splits/train.txt`、`val.txt`、`test.txt`、`data_audit.md`。先冻结 split，之后不能为提高分数临时改变测试集。

**建议 `manifest.jsonl` 的一条样例（字段只是设计建议）**：

```json
{"motion_id":"g1_example_0001","source_motion_id":"seed_session_x_clip_y","csv":"data/g1/raw/example.csv","source_fps":50,"source_format":"seed_euler_deg_cm","start_s":1.25,"end_s":4.75,"text":"A person walks forward and stops.","annotation_type":"fine_grained","split":"train","quality":"pass"}
```

**验收**：有效训练样本数有统计依据；语义标注与时间段人工抽样通过；split 不重叠且同源动作不泄漏。

### S2：建立可逆的数据接口（训练成败关键）

推荐**先统一成 G1 qpos + 明确 fps**，再交给 Kimodo 运动表示：

```text
SEED G1 CSV（原始列、厘米、Euler degree，或你的处理版）
  → 原始解析 / 单位和欧拉角转换 / G1 MJCF 关节映射
  → [T,36] qpos：root xyz (m), quat (wxyz), joint (rad)
  → 30Hz 重采样（平移插值 + quaternion SLERP）
  → Kimodo G1Skeleton34 / FK
  → 计算 smooth root / joint pos / velocity / 6D rotation / contacts
  → 特征归一化（仅基于训练集统计量）
  → x0 [T, D] + text_embedding + valid_mask
```

**官方已有的工具**：`kimodo_convert` 支持 `G1 qpos CSV ↔ Kimodo NPZ`。当前文档明确：`--source-fps 50` 时从 50 → 30 Hz 使用插值；重新计算速度、接触、朝向和平滑 root。**但必须先把原始 SEED CSV 转为符合约定的 36 列 qpos**，否则该命令会错误解释字段。[11]

```bash
# 仅在已经生成无表头、36列、单位正确的 G1 qpos CSV 后使用：
kimodo_convert data/g1/qpos/example_50hz.csv data/g1/kimodo/example_30hz.npz \
  --source-fps 50
```

**必须检查**：

1. 同一个动作 `CSV → NPZ → CSV`，比较 root 轨迹、关节角和 MuJoCo 中的关键姿态；重采样后按共同时间戳比较。
2. 对 6D rotation 逆转换，保证旋转矩阵正交、行列式接近 +1；quaternion 标准化、符号连续。
3. `foot_contacts` 四通道与脚跟/脚尖位置、速度是否一致；跳跃、匍匐、倒地不能统一按走路阈值简单判定。
4. 确认 **Kimodo 内部 y-up、+z forward**，而 MuJoCo CSV 为 **z-up、+x forward**；切换坐标系务必应用于位置与旋转两者。[7]
5. 用官方 G1 数据的相同骨架 XML；如果你后续跟踪策略用另一个 `g1.xml`，务必核对质量/惯量、关节轴/零位/顺序和足部偏移。
6. `stats/motion/` 的规范需参考官方 checkpoint；从零训练使用训练集重新计算并固化自己的归一化统计，验证/测试只读取，不回算。

**验收标准（建议）**：无 NaN/Inf、无明显关节翻转，重采样前后运动路径和关键帧肉眼一致；数值误差阈值用 **100 条检查数据的实际往返误差分布**设定，不应凭空宣称“零误差”。

### S3：Tiny 去噪模型完成从零训练闭环

**只做一件事：证明自己的反向传播和 DDPM 训练实现真的可以学会动作。**

- 选 16–64 段、每段 2–3 秒（60–90 帧）且属于 2–4 个清晰语义动作；固定数据、随机种子、train/val。
- 建议 Tiny：两个 Transformer，每个 `4 layers / latent 256 / 4 heads / FF 1024`，预计约数百万到千万量级参数；**具体值由 `sum(p.numel()...)` 打印确认**，这不是论文公开模型规格。
- 第一步做 **无条件 diffusion**（用全零 text embedding、无约束）验证训练器和生成；第二步再打开真实 LLM2Vec text embedding；第三步恢复原始损失与架构。
- `x0` 回归、随机 `t∈[1,1000]`、高斯噪声、padding mask，推理 DDIM 50/100 steps；必要时先用简化的 normalized SmoothL1/MSE 检查正确性，再引入论文 7 项损失。
- 先冻结 LLM2Vec、预计算文本向量。没有理由在这个阶段对 8B 文本编码器进行反向传播。
- 验证训练时间戳/EMA/模型 state dict、`resume` 能继续更新；保留 `loss_parts`、`grad_norm`、`LR`、`generated_samples`。

**建议最小训练伪代码（需要自行实现，非官方已存在的训练脚本）**：

```python
# train.py（拟新增的训练入口）
# 1. 从 CSV/NPZ 取归一化动作特征 x0, 文本向量 c, padding mask
# 2. 采样 timestep t 和 epsilon，用 DDPM q_sample 构造 xt
# 3. x0_hat = denoiser(xt, pad_mask, c, text_mask, t, ...)
# 4. loss = smooth_l1(x0_hat, x0, mask)  # 调试版
# 5. backward -> optimizer.step -> EMA / logging / checkpoint
# 6. val 阶段用固定 prompt + seed 进行 DDIM 采样与可视化
```

**Go / No-Go**：训练曲线稳定下降且固定 16–64 个样本能够生成可辨识动作；加载 checkpoint 的同种子生成与存盘前一致。如果只能生成静止姿态/随机抖动，**不要直接增加模型规模**。

### S4：Tiny Text-to-Motion（第一份有研究价值的自主结果）

- 数据从 256 → 1,000 → 2,000（建议）逐级增加；尽量让不同类别数量相对均衡。
- LLM2Vec 使用与官方兼容的 `McGill-NLP/LLM2Vec-Meta-Llama-3-8B-Instruct-mntp` + `...-mntp-supervised`，具体权重版本以 `kimodo/model/load_model.py` 为准。[12]
- 每个文本只缓存一个 4096 维句向量，保留原 prompt 文本、encoder 版本和哈希；若论文/代码实际文本张量需要 `[B,1,4096]`，按模型 forward 的 shape 契约组织，不要把普通 Llama next-token logits 当成句向量。
- 把英文 prompt 规范成 `A person ...`；模板化改写仅作为轻量增广，避免把数据原始描述“洗掉”关键信息。原论文用 Qwen3-32B 改写标签，但**不是复现 Tiny 必需条件**。[4]
- 做 **Prompt-swap 实验**：固定噪声 seed 与 duration，输入 `walk / squat / wave / turn`，不同 prompt 生成应体现可识别的动作差异。
- 做 **Text ablation**：真实文本、打乱文本、全零条件三组对比。若三者无差别，说明模型忽略语义条件。

**Go / No-Go**：至少四类训练可见动作能由语义区分，未见过的同类短文本也产生合理运动；TMR/人工盲评等能发现真实文本优于打乱文本。没有基准时不建议随意设“90%文本准确率”。

### S5：Kimodo-Small 结构与训练复现（主里程碑）

建议对齐论文 Small 的思路：两个 Transformer、每个 `8 layers / latent 512`（FF 和其他设置以实际复现代码核对），约 **56M** 可学习参数级别。[4]

1. 使用 S4 已确认的 `KimodoMotionRep`，增至 3–6 秒；逐步扩大至 5k、10k、30k 有效片段。
2. 切换到完整 7 项损失与 FK 约束；区分 raw physical units 和 normalized feature space，**先把每项 loss 的量纲与数值范围打印出来**。
3. 采用 BF16 mixed precision，使用 gradient accumulation 达到合理 global batch；记录实际每 step 时间、峰值显存、samples/s。
4. 对照使用 `AdamW` 和论文 `Adam-atan2` 的效果，但不得将 AdamW 结果声称为完全复现；论文官方 `2e-5` 是大模型参考学习率，Tiny 可另做 `1e-4 / 3e-4` 消融。
5. 保存 latest / best val / EMA checkpoint，并固定验证集。

官方论文 7 项 SmoothL1 loss 权重：

```yaml
# 论文报告的权重，不是可直接用于官方脚本的完整 YAML 配置
loss_weights:
  smooth_root_pos: 10.0
  heading: 2.0
  joint_pos: 10.0
  joint_vel: 3.0
  joint_rot_6d: 10.0
  foot_contact: 4.0
  fk_joint_pos: 5.0
```

**验收**：Small 的多样性、文本契合、脚滑/根轨迹相对 Tiny 有可复现进步；单卡成本有真实 profile，具备扩训决策依据。

### S6：恢复 Kimodo 的“可控生成”能力

这里不要一次塞进全部约束。先用 S5 的 text-only 权重初始化，然后依次增加：

1. **Full-body sparse keyframe**：给第 1 帧或少量帧指定已知全身姿态，训练补全；
2. **Root waypoints / 2D path**：要求轨迹通过指定位置；
3. **Hands / feet end-effector**：稀疏位置、旋转约束；
4. **Foot contact**：某些帧固定脚接触；
5. **Mixing**：两种约束同时生效。

构造目标动作 `x_target` 与二值约束 mask `m`；把 `m*x_target + (1-m)*x_t` 与 mask 作为输入。按照官方论文，阶段二训练会随机采样不同约束图案，约 25% 混合两种约束、10% 无约束；关键帧上限从 1 逐渐增加到 20。先用更简单的约束采样器做通正确性，再对齐官方策略。[4]

**验收**：在相同 seed / prompt 下，约束位置误差显著优于无约束；同时文本与动作质量没有不可接受的退化。建议同时报告生成原始结果和后处理结果。

### S7：全量扩展、长序列与 G1 Sim2Sim

- 仅在 S5/S6 均稳定后才扩到全部合格 SEED G1 样本，并测试类别不均衡采样、语义增广、相邻动作拼接增强。
- **Kimodo 原版训练最长 10 秒**。如果研究 12 秒或更长动作，应单独标注为**超出原始训练长度范围**：先试官方多 prompt 顺序生成 + overlap keyframes / blending，再试 10 秒以上再训练；不能把 12 秒稳定性默认视为原模型能力。[4][6]
- 针对 G1 policy 的 50 Hz 接口，将 Kimodo 30 Hz 动作按时间重采样到 50 Hz（位置插值、旋转 SLERP、速度重算），并通过同一机器人模型与控制器的 Sim2Sim 动作跟踪测试。
- 分开记录：**生成动作在运动学上合理**、**物理仿真可跟踪**、**具有实机部署余量**，三个是不同层级。特别排查速度/加速度/关节限位/自碰撞/脚滑/足端穿地/大力矩风险。

**验收**：完成训练-生成-动力学跟踪的可复现链路；能明确给出哪些 prompt 类别稳定、哪些需要 IK/平滑/动作修复，并保留失败案例。

### 4.2 真正重要的工程测试（建议第一周建好）

- `test_csv_schema`：对于每一版本 CSV，校验列名、列数、单位、无表头/有表头、有效帧数。
- `test_transform_roundtrip`：G1 qpos → Kimodo features → inverse → qpos；一致性、旋转合法性。
- `test_resample`：120/50 → 30 fps，保时长、保关键动作、无 Euler 跳变。
- `test_fk_consistency`：`FK(local_rotations)` 和缓存关节坐标一致。
- `test_cond_mask`：约束值准确覆盖 noisy motion、未约束维保持原噪声。
- `test_diffusion_timestep`：不同 `t` 噪声水平符合设定，输出 x0 shape 正确。
- `test_pad_mask`：变长 batch 的 padding 不参与损失，Transformer attention mask 语义正确。
- `test_checkpoint_resume`：恢复模型+optimizer+EMA+RNG 后与不中断运行在容差范围内一致。
- `test_prompt_swap`：训练后固定 seed 改文本应影响语义动作，不是只换噪声。

### 4.3 单卡 B200 的训练策略

- **文本 encoder 不参与训练**：提前离线批量提取 embedding，并缓存到 CPU/磁盘；避免每个 iteration 都运行 8B LLM2Vec，训练显存和吞吐将明显改善。
- **优化顺序**：先查 CPU 解析 CSV/FK 瓶颈，再看 GPU kernel/attention；尽量离线处理结构化特征，训练读取索引化缓存。
- **混合精度**：首选 BF16；数值敏感的归一化/FK/损失视情况使用 FP32；监控 norm、NaN、OOM。
- **批大小**：从可运行 micro-batch 起做真实 benchmark，使用 gradient accumulation；不直接照抄官方 global batch 2048。
- **训练预算**：先测量 100–300 个 warm-up 后 step 的中位时间、peak VRAM、样本/秒；按照 `总训练时间 ≈ (目标更新数 × 平均秒/step) + 数据准备/评测开销` 制定预算。
- **固定对比**：改变模型大小时，尽量分别对齐“相同训练样本曝光量”和“相同 B200 时间预算”，因为两种比较回答不同问题。
- **设备验证**：B200 的驱动、CUDA compute capability、PyTorch wheel、Transformer/FlashAttention 内核兼容性要在 S0 通过；不能将 RTX 4090/A100 的安装经验直接当成 B200 兼容保证。

## 5. 如何评估：至少四类指标，避免只看视频

| 维度 | 最小阶段（E1–E3） | 扩展阶段（E4–E7） | 解释 |
|---|---|---|---|
| **训练正确性** | train/val loss、不同 diffusion t 的 loss、grad norm、断点一致性 | EMA/非 EMA、稳定性、多 seed | loss 下降不等于生成质量好；过拟合实验是排错工具 |
| **语义控制** | 同 seed 不同 prompt 的人工盲评；打乱文本消融 | TMR 检索 R-precision、文本-运动相似度 | 注意是否有训练/测试源数据泄漏；对比均固定 prompt |
| **运动质量** | 随机样本视频、关节限位、root 漂移、速度/加速度、NaN、脚穿地 | foot-skate（cm/s）、contact consistency、动作多样性、几何异常率 | 评价原始输出与 postprocessed 输出都要记录 |
| **约束遵循** | 起始/终止姿态、单关键帧误差 | full-body、end-effector、2D root path 位置误差 | 误差越小越好；约束越强可能牺牲自然性 |
| **机器人可用性** | MuJoCo G1 模型能正常播放 | 跟踪成功率、完成比例、root-relative/world MPKPE、终止率、动作修复率 | 这属于下游 tracker/物理仿真指标，不是 Kimodo 论文本身的生成质量指标 |

官方 benchmark 的指标实现与完整流水线位于 `kimodo/metrics/`、`benchmark/`；但**其公开基准主要面向 SOMA 骨架**，G1 自训模型不能不经处理就和其 SOMA 论文分数直接比较。建议建立 **同骨架、同 CSV 转换、同测试 prompts/seed、同后处理开关** 的 G1 专项评测，同时引用官方 G1-SEED 作为参考模型。[13][14]

另：官方 2026-10-15 发布的 **SOMA RP v1.2** 修正了与 BONES-SEED 测试序列有关的训练集泄漏。我们的划分应从项目开始就固定，不应直接假设旧版 checkpoint 在任意公开测试数据上完全未见过这些动作。[1]

## 6. 主要风险与止损策略

| 风险 | 早期症状 | 对策 |
|---|---|---|
| **CSV 版本混淆** | 头/脚位置异常、角度爆炸、36 列不匹配 | 先完成 S1 数据契约；原始 SEED 与 Kimodo qpos 严格分离 |
| **模型坐标系/骨架错配** | 动作绕轴旋转、足底高度不对、手腕动作反向 | 核对 `G1Skeleton34`、XML、joint order、y-up ↔ z-up、rest pose |
| **标注与动作时间窗错位** | 文本说“跳”但窗口只有走路/起跳前后混杂 | 用秒对齐，人工复核 fine-grained；样本 ID 可追溯 |
| **模型忽略文本** | 生成平均动作；换文本只改细节 | E2/E3 的 prompt swap、文本打乱消融；类别平衡 |
| **归一化 / FK loss 错误** | loss 数字漂亮但输出位姿严重畸形 | 每项 loss 单位审计；物理空间误差 + 逆变换视频 |
| **扩散条件或 mask 实现错** | 关键帧约束漂移，CFG 对效果无影响 | 单特征和单帧 mask 单测；区分 text dropout / constraint dropout |
| **B200 训练慢/OOM** | 高显存但吞吐不理想、step 时间增长 | 先 profiler；缓存 embeddings/features、减少 sequence、梯度累积 |
| **长序列失稳** | 8–12 秒 root 漂移、脚滑、接缝抖动 | 先 3–5 秒；后扩 10 秒；12 秒优先多 prompt + overlap |
| **生成运动无法真机跟踪** | 仿真摔倒、过流/饱和、关节越限 | Sim2Sim 批量筛选、速度/力矩约束、IK/平滑/动作修复；不直接实机播放 |

## 8. 研究优先级建议与成功定义

**P0：可复现的最小训练闭环。** 从一小部分 SEED G1 数据训练出真正能生成动作的 Tiny Kimodo-like diffusion。此时不追求“惊艳”，追求所有数据、梯度和采样都正确。

**P1：真正文本驱动。** 同 seed 下语义会改变生成动作，而不仅是能输出随机关节序列；通过固定的 held-out prompts 检验。

**P2：尽可能忠实于 Kimodo 的架构与训练。** 从 Tiny 升到官方 56M Small 级别，复用两阶段去噪器、运动特征和论文 loss；实现文本-only → kinematic constraints 课程。

**P3：提高长序列稳定性和机器人可用性。** 先 3–5 秒，再 7–10 秒；如果需要 12 秒，作为单独课题。最后验证 G1 Sim2Sim 跟踪、关节限幅、接触与动作修复。

> **项目成功的最小可接受定义**：不用官方 Kimodo 去噪权重，仅保留预训练的 LLM2Vec 文本编码器，从随机初始化独立训练得到一个 Tiny/Small 去噪器；输入 `A person ...` 英文描述，能够生成语义合理、连续、可导出和可回放的 G1 运动，且有独立测试与消融记录。**这才是“从零复现训练”的第一道明确里程碑**。
