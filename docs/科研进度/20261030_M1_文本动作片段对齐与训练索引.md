## 2. 时间与帧范围规则

每个事件保留 `text_original`、原始起止秒数和事件编号。训练文本仅去除首尾空白，不改写句子，不将整段 overview 强行分配给每个子窗口。

按半开区间 `[start_time, end_time)` 选择实际目标采样时刻 `k/30`，保存 `start_frame` 和 `end_frame_exclusive`。例如 `[4,7)` 秒对应 NPZ 的 `[120:210]` 帧。索引不进行插值或随机时间裁剪。

检查发现 18,267 个事件的终点略超出源时长，最大超出约 `0.033333667 s`。采用固定的边界容差 `1/30 + 1e-6 s`，仅允许小幅越界裁回真实源时域 `[0,N/120]`；更大的越界会拒绝。原始时间、裁回后的时间、裁剪幅度和 `boundary_clipped` 均保留，可追溯检查。不会外推、补帧或复制末帧。

全量结果：

- 352,703 个事件均建立了有效的非空目标帧范围，动作和文本没有未匹配项。
- 18,267 个事件有显式边界修正标记。
- 未发现事件顺序倒置或相邻事件重叠；1,544 个事件前存在超过一个目标帧间隔的间隙。间隙不补造标签或样本。
- 对齐有效不等于默认训练长度合格，也不等于人工确认语义正确。

## 3. 新发现的镜像跨集合问题

此前确认的是官方划分之间没有相同路径或文件名。本阶段增加镜像与原始文件哈希检查，发现 **6,533 个镜像源动作组跨越官方 train 和 test_repetition**。

例如：

```text
train:           220720/mohak_backward_start_001__A031
test_repetition:  220720/mohak_backward_start_001__A031_M
```

两者文件名不同，但属于同一源动作的镜像关系。为避免模型见过测试动作的镜像，本项目在派生索引中隔离对应的 6,533 条官方训练源动作，理由为 `mirror_or_exact_duplicate_of_official_test`。没有删除任何 NPZ、标注或官方列表；完整事件仍在 `segments.parquet`。

官方两个测试集保留原归属。剩余官方训练源动作按 `take_name`、同源镜像关系和完全相同源文件 SHA-256 的连通组进行 train/val 分组。使用固定种子 20261030 对组 ID 哈希，约 5% 的组用于验证。该规则保证本次训练/验证之间没有这些分组重叠；没有宣称验证集的所有语义类别或文本均未见。

实际验证源动作占保留训练范围的约 4.92%；默认配置下 train 和 val 都覆盖 20 个细分类。本划分不是演员身份完全隔离的 subject-held-out 评测，不能据此宣称对未见演员的泛化能力。

官方不同 split 之间仍有 2,396 个共享的 `take_name`，这不自动等于同一份动作；重复测试本来就涉及熟悉动作内容的新实例。没有按这个字段将全部官方训练动作剔除。镜像/完全相同源文件组的跨集合问题单独处理，并由实际审计确认。

**派生训练集因此与官方原始训练样本集合不同。后续比较模型时必须披露这项差异。** 官方 G1 checkpoint 是否见过某些测试动作的镜像不能由本次清理自动排除。

| test_repetition | 6,888 |

## 4. 默认训练片段配置

默认选取 **30–300 帧，含两端**，即按帧数计算约 1–10 秒的完整标注事件。超长事件不直接裁短后复用原描述；过短事件也不填充延长。两者保留在完整事件清单，以便后续有依据地建立其他配置。

| split | 全部事件 | 默认配置中可读取的片段 |
|---|---:|---:|
| train | 290,059 | 247,211 |
| val | 13,900 | 12,146 |
| test_content | 18,619 | 16,393 |
| test_repetition | 15,437 | 12,672 |
| 源动作已隔离 | 14,688 | 0 |
| 合计 | 352,703 | 288,422 |

默认配置排除 64,281 个事件：源动作镜像冲突 14,688、低于最小帧数 36,875、高于最大帧数 12,718。排除理由有优先级，镜像冲突事件不再重复计入长度排除类别。

`test_*.parquet` 是本项目按相同长度规则生成的内部测试事件索引，不是 NVIDIA 完整 Benchmark `testsuite/`，也不能直接用它宣称复现了官方 SOMA 指标。

## 5. Dataset 与 DataLoader

实现位于 [data_pipeline/text_motion_dataset.py](../../data_pipeline/text_motion_dataset.py)。从项目根目录运行：

```python
from torch.utils.data import DataLoader
from data_pipeline.text_motion_dataset import G1TextMotionDataset, collate_text_motion

dataset = G1TextMotionDataset("train")
loader = DataLoader(dataset, batch_size=4, num_workers=0,
                    collate_fn=collate_text_motion, shuffle=True)
batch = next(iter(loader))

print(batch["texts"])
print(batch["motion"]["local_rot_mats"].shape)  # [B,Tmax,34,3,3]
print(batch["motion"]["posed_joints"].shape)    # [B,Tmax,34,3]
print(batch["lengths"])
print(batch["valid_mask"].shape)                # [B,Tmax]，True 表示真实帧
```

初次查看用 `num_workers=0`。多进程脚本应放在 `if __name__ == '__main__':` 入口下；已提供 spawn DataLoader 验证。每个 worker 的 NPZ 缓存默认上限为 128 MiB，可通过 `cache_megabytes` 调整。

Tiny 阶段可筛选已有 2–3 秒事件，而不改变原事件文本：

```python
tiny_pool = G1TextMotionDataset("train", min_frames=60, max_frames=90)
```

Dataset 返回文本、片段 ID、源动作 ID、局部/全局旋转、世界位置、根位置、qpos、原始时间戳和源帧号。世界坐标和单位沿用节点 NPZ；不重新归零 root，不添加 heading 增广。旋转 padding 使用单位矩阵，qpos padding 使用单位根四元数，其余是占位值；所有 padding 必须通过 `valid_mask` 排除出损失和统计量。

加载器有意不返回从完整源动作直接切下来的 smooth-root、速度、接触缓存。后续构造训练特征时，应固定裁剪和初始姿态处理规则，在片段尺度重新计算依赖时间上下文的特征，再仅用训练集拟合统计量。
