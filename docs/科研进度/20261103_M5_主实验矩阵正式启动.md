## 实际冻结的数据规模

原计划明确允许在语义筛选、去重后配额不足时缩小清单。本次六类中抬臂、蹲姿及部分长片段不足以支持原定 10k/30k 配额，最终使用：

| 角色 | 实际规模 | 清单 |
|---|---:|---|
| A 的历史锚点 | 1,024 | `D_anchor_1024.json` |
| B/C 的短片段 | 3,500 | `D_short_3500.json` |
| D/E0 的混合时长 | 3,500 | `D_mixed_small_3500.json` |
| E1 的扩容组 | 4,500 | `D_mixed_large_4500.json` |
| 完整开发集 | 300 | 随上述清单固定 |
| 开发监控子集 | 91 | 随上述清单固定 |
| 封存审计 | 657 | `locked_audit.json` |

扩容实际为 3,500→4,500，约增加 28.6%，不能报告成 10k→30k。每个训练清单保留六类配比、每文本最多 20 条、每源动作组一个事件；混合小集包含于混合大集。未重复填充数量，也未把测试动作搬回训练。

参考审阅发现并在正式训练前排除了倒立行走、持物/曲柄动作、把手或头的转动误归为转身、以及 “turn out the fire” 等词义歧义。此前三版数据及审阅结果分别保存在 `data_pre_review_v1/v2/v3` 和相应参考审阅目录，最终规则为 revision 4。所有修订依据参考动作和原文，未读取 M5 候选的审计分数。

新的 train/val/audit 源组与验证组交集为零；新审计与原 M4 锚点以及已使用的测试源组隔离。真实统计及文件 SHA 见 [data/READY.json](../../runs/m5_20261103/data/READY.json)。

## 吞吐与运行配置

实测 Small 参数量为 **56,755,617**。共享 B200 上，180 帧、BF16、有效 batch64：

| microbatch | 累积次数 | 更新中位耗时 | 峰值 CUDA 分配 |
|---:|---:|---:|---:|
| 16 | 4 | 0.922 s | 2.54 GiB |
| 32 | 2 | 0.511 s | 3.78 GiB |
| 64 | 1 | 0.292 s | 5.91 GiB |

因此 B–F 选择 microbatch64，仍为有效 batch64；A0/A1 保留原 FP32、batch16 和父学习率。测试在同卡有其他任务时完成，属于实际共享负载测量；不把它当作整轮固定完工时间。profile 共执行 1,050 个非正式更新，临时权重丢弃。

profile 使用第一版参考候选测量张量形状与运算成本，其输入身份另存 `benchmark/input_context.json`；正式训练使用最终清理后的清单。原 M2、M4 核心代码和父 checkpoint 未改写。完整性能记录见 [benchmark/report.json](../../runs/m5_20261103/benchmark/report.json)。

每一步实际抽到的样本索引记录在各 run 的 `sample_trace.jsonl`，类别、文本和时长曝光量汇总在 `exposure_counts.json`。恢复时只保留 checkpoint 已提交的抽样轨迹，避免预取或多写日志导致跳过样本。

## 队列顺序与推进条件

```text
A0 控制 → A1 FK（必要时一个 λ=0.25 的 A1b 重试）
→ B0 Tiny → B1 Small → C raw 七项对照
→ D0 短片段继续 → D1 混合时长课程
→ E0 3,500 继续 → E1 4,500 扩容
→ F0 最终匹配 Tiny → F1 独立 Small 完整课程
→ G 开发参考/盲评 → 冻结后独立审计与失败审阅
```

A0 和 A1 都从同一个 R3 20k 完整状态出发，不是 A1 接着 A0 训练。B0/B1 从随机参数开始；C 复用 B1 的随机初始化状态。D/E 成对支路分别使用同一个固定预算终点父 checkpoint。F1 从 seed3102 的随机初始化重复全部 40k→20k→20k 课程。

数值路由在启动前冻结：A 要求 FK 不一致降低至少 10%、核心动作不退化；C 先筛基础生成和回归条件，再按明确的几何分数选择**临时候选**；D 检查长时长与短动作回归；E 必须优于同数据继续训练的控制。未通过就写入 `quality_gate_failed`，不会擅自跳过或无限延长训练。

为使完整矩阵能自动执行，中间候选采用预注册的数值路由，语义结论仍为待审。这与“先完成人工语义选模再继续”的理想流程有区别：若 G 的语义审阅失败，临时候选不能转为正式通过，可能需要后续研究。没有把几何分数或幅度代理改称语义准确率。

G 已保留两名独立评阅者的盲评入口；评分未完成时会停在 `awaiting_independent_human_semantic_review`，而不是伪造人工评分或自动释放测试集。最终审计也有单独的语义与失败审阅。没有验证可用于本次 G1 的 TMR 权重，因此不报告伪造的 TMR/FID。M6 不会自动启动。

启动协议及代码快照：[protocol/launch.json](../../runs/m5_20261103/protocol/launch.json)、`source_at_launch/`。`experiment_registry.json` 是启动时的矩阵登记，动态进度看队列与 run 状态。

浏览 TensorBoard：`http://localhost:6009`，远程 IDE 转发 6009。运行标签包含验证用的 smoke 目录，查看正式结果时筛选 A0/A1/B0/B1 等 run。TensorBoard 使用本次运行独立的临时目录，避免共享 `/tmp/.tensorboard-info` 的权限冲突。

队列进程信息在 `queue_process.json`；需要停止时仅向该队列 PID 发送 SIGTERM，它会转发给当前子进程并在更新边界保存状态。确认旧队列已停止后，可在持久终端恢复：

```bash
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 PYTHONDONTWRITEBYTECODE=1 \
CUBLAS_WORKSPACE_CONFIG=:4096:8 MUJOCO_GL=egl PYOPENGL_PLATFORM=egl \
.venv/bin/python -B -u scripts/run_m5_queue.py --experiment runs/m5_20261103
```

队列有排他锁，按完成标记、配置/数据/代码 SHA 和 checkpoint 身份恢复。若因质量门槛停止，仅重启不会越过门槛；应先读取对应 `decisions/` 与失败报告。正式训练已经开启不代表 M5 已验收，最终状态以后续 `M5_exit_decision.json` 为准。
