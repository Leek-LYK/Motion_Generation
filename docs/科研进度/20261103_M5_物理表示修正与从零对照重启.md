## 1. 为什么先修数据

旧 `m5_research_20261103` 中，独立训练 seed 20261104 的三组都完成了 20k→30k。候选自一致性相对同 seed 六项控制改善 9.8448%，没有达到 10%；最大穿地 10.1207 cm，超过 10 cm。首轮的 10.0679% 改善没有稳定跨过门槛。`candidate.json` 是首轮记录，最终重复结论以 `research_decision.json` 为准。

更重要的是，当前本地冻结转换器将部分非交换的静态旋转与关节旋转按相反顺序组合。MJCF 原生 hinge 的正确关系为 `R_local = R_rest @ R_axis(q)`。旧转换自身的 roundtrip 可以成立，但不保证其 FK 与编译后的 MuJoCo 关节中心一致。

128 个固定随机合法姿态的独立检查中，旧 FK 的最大关节位置误差为 **0.211586 m**，修正版为 **8.38e-16 m**；脚胶囊最低点误差约 8.88e-16 m。旧 skeleton 的中立关节位置不需要改变。这里判断的是当前本地代码，不据此推断官方其他版本的行为。

修正实现放在 `training/g1_physical.py`，没有修改旧 Kimodo 源码。依据见 [physical_contract_audit.json](../../runs/m5_physical_20261103/physical_contract_audit.json)。已经启动的旧表示组合实验保存在 `runs/m5_combined_20261103/`，因该缺陷停止，没有记为训练成功。

## 3. 新训练器与工程证据

新增 `training/m5_physical*.py` 与 `scripts/train_m5_physical.py`，沿用原 Twostage 架构、Root→Body detach、优化器、EMA、条件与采样逻辑。模型显式加载新统计。新的 checkpoint schema 拒绝把旧表示模型作为续训来源。

六维旋转使用同一列约定的 Gram–Schmidt；近零或共线输入有确定性有限值回退，并记录回退比例。回退本身不算旋转可实现性改善。可选单轴项使用 `R_rest.T @ R_local` 与原生轴，本轮四个主对照尚未加入单轴、自一致性或地面附加项。

已通过的验证包括：

- 真实动作作预测时，七项目标约 2.17e-13，FK 自一致性约 7.69e-8 m，原生单轴能量约 3.87e-15。
- 受控旋转扰动提高误差并产生有限梯度；位置与旋转两条分支有梯度。
- padding 的损失与梯度为零；变长 microbatch 按有效帧累积，梯度最大差约 7.3e-12。
- yaw 下骨架距离、胶囊高度误差均低于 1e-6 m。
- BF16 完整更新和 checkpoint 恢复逐位一致；六类动作的实际评估与 qpos/特征导出通过数值检查。
- 四个真实 Tiny/Small CLI 进程各完成 16 步试运行；Tiny 两分支初始权重相同，Small 两分支初始权重相同，四组数据抽样轨迹 SHA 完全一致。

证据：[verification/report.json](../../runs/m5_physical_20261103/verification/report.json)、[parallel_pilot_report.json](../../runs/m5_physical_20261103/verification/parallel_pilot_report.json)。试运行不参加模型排名。

新视频导出器 `scripts/export_m5_physical_video.py` 已用工程 checkpoint 实际生成并检查 75 帧、1280×720、30 FPS 的 MuJoCo MP4，核对了文件哈希与画面。工程视频使用独立目录和 schema，不进入正式索引。证据：[video_export_report.json](../../runs/m5_physical_20261103/verification/video_export_report.json)；使用方法见 [视频导出与归档规范](../说明文档/视频导出与归档规范.md)。

microbatch 16 与 64 分别测量 Tiny/Small 的 90/180 帧各 200 次更新，合计 1,680 次工程更新；另有少量恢复/并行验证，总量在本轮 3k 工程预算内。有效 batch 始终为 64。microbatch 64 的短片段更新约 Tiny 0.053 s、Small 0.071 s；Small 180 帧峰值约 5.91 GiB。正式使用 microbatch 64。单进程 profile 只是成本参考，并发与完整评估耗时由实际日志更新。

## 4. 四组正式训练

四组并行，共 **160k 新 optimizer updates**。训练数据均为合格短片段 3,404 条。BF16 前向、FP32 几何与参数、batch64、AdamW 2e-5→2e-6、1k warmup；前 5k 均匀时间步，之后 50% 高噪声替换；text dropout 0.1、全局 yaw 增强、网络 dropout 0。文本模型不训练，去噪器不加载官方预训练权重。

P0/B0 是新数据和新初始化下的修复诊断，不是旧 R3 续训实验的改名。旧 A 的失败不变；仍明确检查自一致性至少改善 10% 的条件。B0/B1 回答容量差异，B1/C 回答损失量纲与权重差异。C 只复用初始权重，不加载 B1 已训练参数。

每 1k 做去噪诊断，每 2k 做 91 条监控生成，每 10k 与 40k 终点做完整 300 条开发生成。完整生成固定 DDIM100、CFG2、采样 seeds 0/42/1234、native/heading=0。最终比较固定使用 40k；保存中间 checkpoint 不代表可以事后挑选有利终点。
