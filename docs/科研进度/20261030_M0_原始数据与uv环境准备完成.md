### 3.2 原始 G1 CSV 契约

原始动作位于 `g1/csv/{date}/{filename}.csv`，源数据采用 120 Hz。已检查的格式为有表头的 **36 列**：

| 内容 | 列数 | 当前转换约定 |
|---|---:|---|
| `Frame` | 1 | 帧编号；与秒和采样率的关系需在全量审计中检查 |
| `root_translateX/Y/Z` | 3 | 厘米；转换为米 |
| `root_rotateX/Y/Z` | 3 | Euler 角，度；当前验证使用 `Rotation.from_euler('xyz', ..., degrees=True)` |
| 29 个 `*_joint_dof` | 29 | 关节角，度；转换为弧度，并按机器人关节名称映射 |

**原始 CSV 的 36 列与 Kimodo qpos CSV 的 36 列含义不同。** 标准 qpos 应为：

```text
root_xyz_m（3） + root_quaternion_wxyz（4） + joint_angles_rad（29）
```

官方 qpos 导入路径使用无表头、无 `Frame`、无时间戳的数值矩阵。不能直接把原始 SEED CSV 交给 `kimodo_convert` 的 qpos 路径。已有本地 Kimodo HTTP 服务输出的 37 列带时间戳 CSV 也需单独解析。

G1 qpos 包含 29 个驱动自由度；`G1Skeleton34` 指 34 个骨架节点，不能将其理解为 34 个驱动自由度。后续 FK 和特征生成要采用对应的 Kimodo 骨架及坐标变换，不混用历史 13 节点跟踪特征或 Human 26 节点表示。

| 字段 | 后续用途 |

| `move_duration_frames` | 帧数、时长与标注边界核验的参考值 |

### 3.4 时间轴标注如何使用

当前 JSONL 的顶层字段为 `filename`、`num_events`、`events`；每个事件包含：

```text
events[].start_time    # 秒，相对完整源动作
events[].end_time      # 秒，相对完整源动作
events[].description   # 对应区间的英文动作描述
```

已记录的检查结果：142,220 个唯一动作名、352,703 个事件，没有重复动作名；有限时间值且 `0 ≤ start_time < end_time` 的检查通过，未发现空白描述。本次补充统计得到 **48,424 个按原始字符串精确去重的事件描述**，可作为后续文本缓存规模的参考；该数字不是语义类别数，加入整段描述、模板或改写后缓存数量会变化。

这份本地 JSONL **没有** `overview_description` 和 `propagated_from_filename` 字段。整段描述应从元数据选取；如后续研究需要区分人工标签和传播标签，再核对并准备 NVIDIA 独立时间轴标注。

尚未完成的检查包括：所有事件是否位于实际动作时长内、事件覆盖和重叠情况、镜像左右描述、全量时间对齐，以及抽样视频的语义核验。352,703 个事件也不能直接等同于 352,703 个最终合格训练样本。

## 6. 转换验证与已知问题

成功样本来自原始文件 `g1/csv/230425/jump_ff_360_R_001__A351_M.csv`，取前 240 帧，执行：

```text
120 Hz 原始 CSV → 单位/旋转/关节映射 → 120 Hz qpos
→ kimodo_convert → 30 Hz Kimodo NPZ（60帧）
→ 30 Hz qpos（60×36）
```

NPZ 七个字段和回转 qpos 均为有限值。与输入每四帧比较：root 位置最大差约 `2.9e-8 m`，根旋转最大夹角约 `1.0e-5°`，关节角最大差约 `0.0125°`。这是单条动作的数值闭环结果，尚无全量回放、接触质量或物理跟踪结论。证据见 [冒烟检查报告](../../reports/env_smoke_20261030/README.md) 和同目录输出。

另一个来自历史 `seed5000_0501` 的 50 Hz 样本，原始 qpos 有限，但经当前 `kimodo_convert --source-fps 50` 后出现 NaN。最小检查发现：[motion_io.py](../../../kimodo/source/kimodo/exports/motion_io.py) 中 `_quaternion_slerp(q, q, t)` 在单位四元数相同、内积为 1 时返回零四元数，后续转旋转矩阵产生非有限值。相关输出已标为 `FAILED_50hz_*`，不得作为训练输入。

后续主数据源采用本次原始 **120 Hz** 数据；当前 120→30 Hz 的整数倍抽帧避开了该插值分支。若需处理历史 50 Hz、其他非整数倍帧率或任意时间插值，先修复并回归测试相同旋转、近似相同旋转、`q/-q` 等情况，再扩大使用。本阶段没有修复兄弟项目中的转换源码。

## 7. 后续如何使用：从原始资料到训练数据

下一目标是 **M1：形成可追溯的全量 30 Hz 数据处理流程及训练数据契约**。先用分层抽样确认转换与时间对齐，再运行全量处理；Tiny/Small 使用同一全量 manifest 中的固定子集，避免每个实验维护一套不同的数据口径。

| 顺序 | 要完成的工作 | 预期交付与通过条件 |
|---|---|---|
| 1 | 固定源版本、处理 36 条差异，建立源动作级 manifest | 每条动作可追溯到原始 CSV、元数据、标注与官方 split；缺失和排除有记录 |
| 2 | 全量 schema/帧数/时间边界审计，分层抽样 100–200 条核验 | 核对实际帧数、120 Hz 时间轴、单位、关节顺序、根坐标和镜像语义；报告不一致样本 |
| 3 | 验证 120→30 Hz 转换、FK 与往返，再批量处理 | 保存标准 qpos 与 Kimodo NPZ；检查有限值、旋转合法性、时长、关键姿态与足端接触；失败样本隔离 |
| 4 | 用事件时间窗建立片段级 manifest，并从训练范围分组划出验证集 | 使用秒对齐 `[start_time, end_time)`；同源窗口和镜像不随意跨 split；测试集保持冻结 |
| 5 | 从训练部分计算特征统计，缓存去重文本向量 | 验证/测试不参与统计；特征与文本缓存带版本和来源；抽样逆变换及文本检查通过 |
| 6 | 补齐新环境下的官方推理基线，再启动 Tiny 排错实验 | 固定 prompt/seed、记录 raw/postprocess；Tiny 去噪器随机初始化，先 16–64 段过拟合，再做文本对照 |

建议片段 manifest 至少包含：`motion_id`、`source_motion_id`、`filename`、原始路径、源哈希、`is_mirror`、来源分组、官方 split、最终 train/val/test、事件编号、原始英文文本、起止秒数、源帧数/FPS、目标帧数/FPS、处理产物路径、质量状态与排除原因。**这些是下一步拟建立的字段，当前尚无此训练 manifest。**

裁剪窗口时要保留其在完整动作中的起始时间；用目标采样时刻落入 `[start_time, end_time)` 来确定帧，不能把原始 120 Hz 帧编号直接当作 30 Hz 下标。整段 overview 描述也不能直接用于只包含局部动作的窗口。前后裁剪、root 平移或 heading 增广需同步影响相关特征与约束。

特征应复用当前 [KimodoMotionRep](../../../kimodo/source/kimodo/motion_rep/reps/kimodo_motionrep.py) 的实际布局：G1 总维度 **417 = 5 维 global root + 412 维 body**，还需独立的 **4 维 local root** 统计。当前拼接顺序为平滑 root、heading、关节位置、6D 旋转、速度、接触；不要按说明文中的表格顺序自行拼接。关节位置以平滑 root 为参考，转换时遵循源码的具体定义。

文本侧使用预训练 LLM2Vec 并冻结。先按精确文本去重缓存，保留编码器权重、tokenizer、提示模板、精度与版本信息；优先沿用已验证的内部 `batch_size=1`。既有 [LLM2Vec 审计报告](../../../kimodo/experiments/llm2vec_adapter_audit/report.md) 记录了变长左 padding 的 attention 边界，不能只为加速就直接增大内部 batch。

拟新增的处理结果目录可放在 `data/processed/`，训练过程放在 `runs/` 或项目内统一约定的实验目录。当前没有生成全量 417 维特征、训练集统计量、文本 embedding 缓存、Tiny/Small 模型、正式评测结果或 Sim2Sim 成功率；原始数据数量不能替代这些交付。
